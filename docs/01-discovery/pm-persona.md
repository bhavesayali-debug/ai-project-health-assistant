# Target User Persona — IT / Software Project Manager

## 1. Persona Overview

**Role:** IT / Software Project Manager

The primary user for the AI Project Health Assistant is an IT or Software Project Manager responsible for coordinating delivery across multiple teams and maintaining a reliable view of overall project health.

The Project Manager needs timely and accurate project information in order to make informed decisions, communicate status, and identify areas requiring attention or escalation.

---

## 2. Project Environment

The Project Manager typically works within an Agile or hybrid software delivery environment involving multiple cross-functional teams and stakeholders.

The project may involve:

- Development teams
- Product Owners
- Scrum Masters
- Quality Assurance teams
- Business Analysts
- Technical leads
- Business stakeholders
- External vendors or dependent teams

Because multiple teams contribute to the project, information about delivery progress may be generated across several systems and communication channels.

---

## 3. Key Responsibilities

The Project Manager is responsible for:

- Maintaining visibility into overall project progress
- Monitoring project milestones and delivery commitments
- Identifying and managing risks, issues, blockers, and dependencies
- Understanding the impact of delays or changes
- Coordinating activities across cross-functional teams
- Monitoring important action items
- Communicating project health to stakeholders and leadership
- Escalating concerns when required
- Supporting timely project decisions using reliable information

A key responsibility is ensuring that the reported project status accurately reflects what is actually happening across the project.

---

## 4. Common Tools and Information Sources

The Project Manager may use information from:

- Jira
- Confluence
- ServiceNow
- Microsoft Project or project plans
- Microsoft Teams
- Outlook / Email
- Defect tracking systems
- Risk registers
- Issue registers
- Sprint updates
- Meeting notes
- Milestone trackers
- Action-item trackers

These tools often contain different pieces of the overall project picture.

---

## 5. Main Challenge

The Project Manager must invest significant time reviewing and correlating information from multiple sources before obtaining an accurate and current view of project health.

Important information may be:

- Distributed across several tools
- Updated at different times
- Buried within large volumes of project communication
- Inconsistent between sources
- Difficult to correlate quickly
- Relevant to another milestone or dependency that is not immediately obvious

As a result, understanding the true status of the project can require significant manual effort.

---

## 6. Desired Outcome

The Project Manager wants to:

- Quickly understand the current health of the project
- See important project information in a consolidated view
- Identify areas that require immediate attention
- Understand risks, issues, dependencies, and milestone concerns
- Reduce the time required to manually consolidate project updates
- Communicate project status clearly to stakeholders and leadership
- Have enough supporting information to make informed decisions

The ideal experience should allow the Project Manager to understand the most important project-health signals at a glance while still being able to investigate the underlying details when required.

---

## 7. Primary User Need

> **As an IT / Software Project Manager, I need a reliable and consolidated view of project health so that I can quickly identify delivery concerns, make informed decisions, and communicate accurate status to stakeholders.**

---

## 8. Persona Success Statement

The Project Manager should be able to answer:

> **What is the current health of my project, what requires my attention, and why?**

without having to manually review every individual project source first.
